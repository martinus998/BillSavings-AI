Security

Current public-preview security status

Sensitive uploads and paid checkout remain disabled until the production backend, private storage, authentication and payment links are fully connected and tested.

Our production security approach

Private document storage

Uploaded bills are intended to be stored in authenticated private storage, not inside the public website repository.

Least-privilege access

Production access controls are designed so users can access only their own data and authorized server-side services receive only the permissions they need.

Payment separation

Full payment-card details are intended to remain with the payment processor rather than being stored by BillSavings AI.

Automated checks

The public repository uses automated checks intended to catch common credential formats and prevent sensitive files from being published accidentally.

Preview limitations

The current deployment is suitable for public marketing content but is not the final storage layer for private bills, bank statements or medical documents. Do not submit sensitive documents until the interface clearly indicates secure upload is active.

Security reporting

If you discover a potential security issue, use the current channel on our Contact page. Please do not publicly post credentials, private customer information or exploit details.

No overstatement

We do not claim that any online service is perfectly secure. Security controls evolve as the production service changes.
